# 반드시 지킬 규칙

어기면 점검이 실패하거나, 화면이 깨지거나, 수업 내용이 틀린다.

## 표기와 금지 내용

- 음운은 언제나 빗금 `/ㄱ/`·`/j/`, 발음은 대괄호 `[궁물]`, 표기는 원고 그대로. 화면 문구에 빗금 없는 자모가 있으면 실패한다 — `text.js`는 `check-text`, 지침 문장(`guides.js`)은 `check-rules`의 지침 문구 단계가 본다.
- 대괄호는 발음 표시 전용이고 `G.text.pron`만 만든다. 문구 파일에 실제 낱말의 발음을 적지 않는다(뽑힌 원고의 답이 샌다).
- 화면에 쓰면 안 되는 것: '글자'(소리를 문자로 부르는 말 — 화면 글 점검이 잡는다), 한자, '게임오버', 실제 방송사·인물 이름, 훈민정음·해례·중세국어·제자 원리·조선 소재. 금지 낱말·방송사 이름 목록은 `tests/lib/words.mjs` 하나에 두고 문구 점검과 화면 글 점검(`check-screen-text`)이 함께 쓴다.
- 학년별 문구는 `{ m3, h1 }` 꼴이고 두 학년의 키 구조와 `{이름}` 자리가 같아야 한다(`check-text`).
- 한 줄 자리(신호·안내·확인·단추·머리)는 대략 30자 이내, 줄바꿈 문자 없음. 여러 줄은 게임 방법 창과 조항 공개 머리 문장만.

## 내용의 진실

- 원고·지침 예시·조항은 `design/research/03`의 원문 대조본(§2 표준 발음법·한글 맞춤법 원문, §4 지학사 교과서, §5 현행 고시 대조)에 있는 것만 쓴다. 원고마다 `src`에 출처 쪽을 적는다. 대조되지 않은 예시(읽고, 밭이랑 등)는 넣지 않는다.
- 분석이 갈리는 낱말(되어→돼 등)은 원고에 넣지 않는다. 표준 발음이 애매하거나 교과서마다 갈리는 것을 만나면 임의로 정하지 않고 `docs/tracking/findings.md`에 적은 뒤 선생님께 묻는다.
- 원고를 더하거나 고치면 엔진 대조(`check-rules`)가 통과해야 한다: 엔진 도출 = 표준 발음, 풀이 과정의 모든 단계가 규칙 안, 음운 수·변동 횟수가 데이터와 같음, 어떤 순서로 규칙만 적용해도 같은 발음.
- 지침 예시는 그 지침 빈칸 조건을 보기마다 적어도 한 번 보여야 한다(`G.rules.checkGuides`가 빈 목록을 돌려야 함).

## 모듈 경계

- 층 순서 util → data → core → game → main. 아래 층이 위 층을 부르지 않는다. `index.html`의 등록 순서가 이 순서를 따른다(game 층 안의 차례는 상관없다 — 화면은 이름으로 늦게 찾음).
- 스크립트는 모두 `'use strict';`로 시작하고 전역은 `G.<이름>` 하나 또는 데이터 `window.이름` 하나만 연다. ES 모듈·빌드 도구·npm 의존성·프레임워크를 쓰지 않는다.
- `G.rules`는 순수 함수만: DOM·저장소·시간·난수 전역을 쓰지 않고(난수는 시드로 받음), 받은 값을 바꾸지 않고, JSON으로 옮길 수 있는 값만 돌려준다. 화면 문장을 만들지 않는다.
- 판정·뽑기·채점·연음 자리·닮은 칸·쌍둥이·원고 결과·공개 조항·장 합계는 `G.rules`만 정한다. 화면 파일에서 규칙 id·조항 번호로 분기해 판정을 흉내 내면 결함이다.
- `js/core/util.js`·`rules.js`·`hangul.js`·`save.js`는 Node 점검이 `document` 없이 불러온다 — 불러올 때(최상위) `document`에 닿으면 안 된다.
- 화면 문구는 `js/data/text.js`(지침 문장은 `guides.js`, 조항 원문은 `articles.js`)에서만 꺼낸다. 화면 파일에 한국어 문장을 직접 쓰지 않는다.
- 화면은 `G.screens.<이름> = { mount, unmount }`로 등록하고 화면 파일끼리 직접 부르지 않는다(넘어갈 때는 `G.app.go(이름, 값)`). 새 화면 이름은 `js/game/app.js`의 `NAMES`에 더한다 — 목록에 없는 이름은 시작 화면으로 간다.
- 저장은 `G.save`만 localStorage에 닿는다. 저장 모양을 바꾸면 `SCHEMA`를 올린다.

## 점검 관문

- 병합·push 전에 `cd tests && npm test`가 마지막 줄 '모두 통과', 종료 코드 0. 실패한 채로 합치지 않는다.
- 브라우저 점검은 aside CLI로만 한다. playwright MCP로 브라우저를 직접 몰지 않는다(코드로 쓴 E2E 프레임워크와는 별개).
- 점검용 조작(`G.review.debug`, `tests/lib/runs.mjs`)은 점검 대본·점검 페이지에서만 쓰고 게임 화면에 단추·글로 드러내지 않는다.
- 점검 대본은 성공하면 `PASS`, 실패하면 throw·`FAIL`로 끝난다. 화면 캡처는 `tests/shots/`(저장소 제외).

## 화면 표현

- 색은 `css/base.css`의 토큰만 쓴다(생 색값 금지). 신호 색·선택 색·경계 종류 색의 역할을 섞지 않고, 신호는 색 + 기호로 구분한다. 다크 모드는 없다.
- 정확해야 하는 것(음절 블록·형태소 경계·교정 부호·조음 도표·프롬프터·신호 기호)은 코드로 그린 SVG·DOM이다. 깜박임 반복이나 계속 움직이는 장식이 없다. `<html class="reduce-motion">`이면 연출을 건너뛴다.
- 기준 크기 다섯(1280×800, 1366×768, 360×740, 390×844, 1920×1080)에서 가로 스크롤이 없고, 누르는 자리는 가로 배치 64px·휴대폰 세로 48px 이상. 높이가 낮은 가로 화면(휴대폰 가로)에는 '세로로 돌려 주세요'를 덮는다.
- 글꼴은 `css/fonts.css`(만들어진 파일, 손으로 고치지 않음)의 GamsuPron(발음·제목)·GamsuUI(안내 글). 화면 문구에 새 글자가 생기면 `python tools/build_fonts.py`를 다시 돌리고 결과를 함께 커밋한다.

- 저장소에 올리지 않는 것: `tools/fonts_src/`(원본 글꼴), `assets/raw/`(그림 원본), `tests/shots/`, 교과서 PDF.
