# 명세 — 구현 2단계: 1·2장 연습 한 판 (발음 감수실)

구현 2단계(1·2장 연습 한 판)를 만들 때 선생님과 확정한 명세다. 코드 주석의 "명세 §N"은 이 문서의 절 번호를 가리킨다. 그 뒤의 결정은 `docs/tracking/decisions/`가 이긴다.

## 1. 목표와 까닭

- **목표**: 학생 한 명(또는 모둠)이 교실 기기에서 1·2장을 처음부터 끝까지 연습할 수 있게 한다. 흐름은 시작 화면 → 감수 지침 채우기 → 원고 7개 감수·송출 → 실제 조항 공개 → 장 결과다.
- **까닭**: 선생님이 플레이 테스트를 수업 흐름 그대로 해 보고 판정·조작·문구를 검토하려는 것이다. 규칙 엔진과 1·2장 원고 82개는 이미 있고 점검도 통과한다(`js/core/rules.js`, `js/data/scripts.js`, `cd tests && npm test`).
- **함께 하는 것**: 소리 장치(파일은 아직 없음), 효과음·배경 음악 후보 목록, 그림 화풍 견본 2~3장, 글꼴, 이어 하기.

## 2. 범위

**포함**
- 시작 화면, 게임 방법 창, 설정(소리·움직임 줄이기)
- 감수 지침, 감수 화면(교정 부호 넷·조음 도표·송출·신호·도움), 조항 공개, 장 결과
- 이어 하기
- 화면 크기 세 종류: 태블릿·노트북 가로, 휴대폰 세로, 전자칠판 1920×1080
- 소리 장치와 후보 목록
- 화풍 견본
- 글꼴

**제외(다음 차례 이후)**
- 3~8장 규칙과 원고
- 대결 모드(결정 0006)
- 감수 수첩(누적 기록)
- 결과 화면의 알아 두기·생각해 볼 질문·캡처 제출
- 자막 책상(결정 0005)
- 실제 그림 넣기(고른 화풍으로)
- 음원 파일 넣기와 '만든 사람·출처' 화면
- 배포(GitHub Pages 켜기)
- 교사용 기능

## 3. 변하지 않는 원칙 (어기면 안 됨)

1. **판정의 진실은 `G.rules` 순수 함수에만 있다.**
   - 원고 뽑기, 쌍둥이 원고 찾기, 지침 채점, 공개할 조항 고르기, 닮은 칸, 연음 자리, 송출 신호는 모두 `G.rules`가 정한다.
   - 화면 코드는 그 결과를 그리기만 한다. `rules.js`와 `js/data/*`는 DOM·`localStorage`·타이머를 쓰지 않는다(Node `vm`에서 그대로 불러 점검).
2. **조작 동사는 교정 부호 넷**(고침표·뺌표·넣음표·합침표)과 되돌리기뿐이다. 형태소 경계를 긋는 조작은 없다(결정 0007).
3. **오답을 막지 않는다.**
   - 어떤 부호든 어떤 음운에나 쓸 수 있고, 판정은 송출할 때 한다. 연습의 송출 횟수에는 제한이 없다. '게임오버'라는 말은 쓰지 않는다.
   - 예외: 물리적으로 할 수 없는 교정(넣을 빈자리가 없음, 이웃하지 않은 두 음운 합치기)은 그 자리에서 한 줄로 알리고 감수 기록에 넣지 않는다. 정답에 관한 정보는 주지 않는다.
4. **신호는 네 가지뿐이다**: 온에어 성공 / 결과는 맞지만 규칙 밖 / n곳이 다름 / 표준 아님(`G.rules.broadcast`의 `onair`·`offrule`·`diff`·`nonstandard`).
5. **아직 얻지 않은 답은 화면 글·DOM·aria 어디에도 새면 안 된다.**
   - 장 결과 전까지의 표준 발음과 그 원고의 풀이 과정
   - 심화 단계의 형태소 경계(종류 포함)
   - 원고의 함정 여부와 비표준 발음 목록
   - 지침 빈칸의 정답
   - 예외는 **기본 단계의 도움 장치 두 가지뿐**이다: 한자어 구성 경계의 '한자어' 이름표(제20항 다만 낱말에만 붙어 그 낱말이 예외임을 드러냄 — 결정 0007의 의도, 신라·난로와의 대비)와 닮은 칸 안내. 심화 단계에서는 둘 다 없다.
6. **표기 규칙**
   - 음운은 `/ㄱ/`, 발음은 `[궁물]`, 표기는 원고 그대로 적는다.
   - 화면 어디에도 '글자'라는 낱말을 쓰지 않는다('표기'로 쓴다). 금지 낱말은 음운 해전과 같다(글자, 훈민정음, 해례, 제자 원리, 상형, 가획, 중세, 조선 수군, 판옥선, 협선, 척후선, 게임오버).
   - 한자를 화면에 쓰지 않는다(고1 용어도 '비음화'처럼 한글 한자어만).
   - 실제 방송사 이름·로고·인물을 쓰지 않는다.
7. **네트워크로 아무것도 보내거나 불러오지 않는다.** 글꼴·그림·소리는 모두 저장소에 동봉한다. `index.html` 더블클릭(file://)과 정적 서버 둘 다에서 콘솔 오류 없이 돈다.
8. **학년 차이는 문구와 용어만이다.** 학년에 따라 `G.rules`를 나누지 않는다.
9. **학생 개인정보는 받지 않는다**(이름 입력 없음). 기록은 그 기기 브라우저에만 남는다.

## 4. 화면 흐름

```
시작 ──[장 고르기]──> 감수 지침 ──> 원고 감수 1/7 … 7/7 ──> 조항 공개 ──> 장 결과
  │                                                                        │
  └─[이어 하기]──> (저장된 자리)                         [다시 하기] → 같은 장 새로 뽑기(지침 건너뜀)
                                                          [장 고르기] → 시작
```

- 게임 방법 창은 시작 화면과 감수 화면에서 열 수 있다.
- 설정은 시작 화면에서 연다. 감수 중에는 화면 구석의 소리 켜기/끄기만 둔다.

## 5. 시작 화면

1. **학년**: 중3 / 고1(마지막 선택을 기억). 문구·용어만 바뀐다.
2. **장 목록**: 8장 이름을 모두 보인다(기획안 3절의 장 이름). 1·2장만 누를 수 있고 3~8장은 '준비 중'이다. 1·2장에는 중3에게 권한다는 표시를 둔다.
3. **단계**: 기본 / 심화. 장마다 고른다(마지막 선택을 기억).
4. **이어 하기**
   - 진행 중인 장이 있으면 [이어 하기]와 함께 '몇 장·어느 단계·원고 몇 번째'를 보인다.
   - 진행 중인 장이 있는데 새 장을 시작하면 "진행 중인 장이 지워져요"를 한 번 묻는다.
5. **[게임 방법]**: 처음 여는 기기에서는 '처음이라면 먼저 보세요' 표시를 붙인다(한 번 열면 사라짐).
6. **설정**: 배경 음악 켜기/끄기·음량, 효과음 켜기/끄기·음량, 움직임 줄이기. 기기에 저장한다.

## 6. 원고 뽑기 (결정 0012 + 이번 결정)

장을 시작할 때마다 `G.rules`의 순수 함수가 원고 7개를 뽑는다. 난수는 시드를 받는다(점검에서 결정적으로).
- **뺄 원고**: 그 장 감수 지침의 예시 원고는 뽑지 않는다.
- **1장**: 함정 2개(연음 함정 `trap: 'link'` 가운데) + 일반 5개(끝소리 규칙 원고 가운데). 일반 5개에는 제15항 원고(모음으로 시작하는 실질 형태소·다음 단어 앞)가 지침 예시로 쓰이고도 남아 있으면 적어도 1개 넣는다(§12의 원고 보강).
- **2장**: 함정 2개 = 제20항 다만(`trap: 'exception'`) 1개 + 감기(`trap: 'nonstandard'`) 1개로 **고정**. 일반 5개에는 비음화(제18항)·ㄹ의 비음화(제19항)·유음화(제20항) 원고가 각각 적어도 1개씩 들어간다.
- **원고 갈래**: 풀이 과정에서 끝소리 규칙이 아닌 첫 규칙으로 정한다(짓는·놓는·책 넣는다 → 비음화, 막론·협력 → ㄹ의 비음화, 물난리 → 유음화). 끝소리 규칙만 쓰면 끝소리 갈래, 함정은 함정 종류가 갈래다.
- **순서**: 7개의 순서와 함정 위치는 무작위다.
- **불가능하면 오류**: 조건을 채울 수 없는 원고 풀이면 함수가 오류를 던진다(데이터 잘못 — 점검이 잡음).

## 7. 감수 지침 (규칙 발견)

1. **장마다 지침 여러 개를 한 화면에 둔다.** 지침은 실제 조항 원문(§12에서 대조한 것)에서만 만든다. 지침 문장 초안은 에이전트가 쓰고 플레이 테스트에서 선생님이 검토한다.
   - **1장 지침 3개**
     - ① 끝소리 규칙(제8·9항)
     - ② 모음으로 시작하는 형식 형태소 앞의 연음: 홑받침·쌍받침은 그대로 옮김(제13항), 겹받침은 뒤엣것만 옮김(제14항)
     - ③ 모음으로 시작하는 실질 형태소나 다음 단어 앞에서는 끝소리 규칙 뒤 연음(제15항)
   - **2장 지침 3개**
     - ① 비음화(제18항)
     - ② ㄹ의 비음화: 받침 ㅁ·ㅇ 뒤, ㄱ·ㅂ 뒤(제19항·붙임)
     - ③ 유음화(제20항)와 '다만' — 의견+란처럼 [ㄴ]으로 발음하는 낱말
2. **빈칸**: 지침마다 빈칸이 1개 이상이고, 빈칸마다 보기를 2~4개 고른다(빈칸 하나에 답 하나). 보기 안의 음운은 빗금 표기다.
3. **예시**
   - 지침마다 예시 원고(표기 → 표준 발음 쌍)를 3~4개 **고정**해 둔다. 예시는 그 지침의 빈칸 조건을 보기마다 적어도 한 번씩 보여야 한다. 예를 들어 비음화 지침이면 받침 /ㄱ/·/ㄷ/·/ㅂ/과 뒤 /ㄴ/·/ㅁ/이 모두 나와야 한다.
   - 지침 데이터에 예시마다 무엇을 보이는지 적고, 점검이 엔진으로 확인한다.
   - 예시 원고는 `js/data/scripts.js`의 원고 id로 가리킨다(원문 대조된 것만).
4. **채점**
   - 빈칸을 모두 고른 뒤 [확인]을 누르면 화면의 모든 지침을 한 번에 채점한다. 틀린 칸이 있으면 "n칸이 맞지 않아요"처럼 **수만** 알린다. 어느 칸인지, 정답이 무엇인지는 알리지 않는다.
   - 다 맞을 때까지 다시 고른다. 몇 번 틀렸는지는 기록하지 않는다.
   - 채점은 `G.rules`의 순수 함수(지침, 고른 값 → 틀린 칸 수)가 한다.
5. **다 맞으면** 감수로 넘어간다. 장 결과에서 [다시 하기]로 같은 장을 다시 할 때는 지침을 건너뛴다(그 판에서 이미 채운 것으로 본다).

## 8. 감수 화면

### 8-1. 보이는 것

- **머리**: 장 이름, 원고 번호(n/7), 음운 수 '표기 n → 지금 m'(교정할 때마다 저절로 바뀜), 단계 표시.
- **원고 표기**: 원고에 적힌 그대로.
- **음절 블록**
  - 음절마다 초성·중성·종성 자리를 보인다. 초성 'ㅇ'은 빈 자리(○)로 그려 음운이 아님을 보인다.
  - 반모음이 있는 음절은 반모음 자리를 따로 보인다(ㅕ = j + ㅓ). ㅢ는 나누지 않고 한 칸에 보인다(결정 0009).
  - 겹받침은 종성 자리 안에 두 음운으로 보인다.
  - 교정한 결과가 블록에 바로 반영된다.
- **형태소 경계(기본 단계만)**
  - 음절 사이에 '+'를 그린다. 종류에 따라 색·굵기를 다르게 하고 작은 이름표를 단다(결정 0007을 이번에 고쳐 적음).

    | 종류(`cuts`) | 중3 이름표 | 고1 이름표 |
    |---|---|---|
    | `formal`(뒤가 형식 형태소) | 뒤에 붙는 말 | 형식 형태소 |
    | `content`(뒤가 실질 형태소) | 뜻이 있는 말 | 실질 형태소 |
    | `sino`(한자어 구성, 제20항 다만 낱말만) | 한자어 | 한자어 |
    | `space` | (띄어쓰기 틈으로만 보임) | (같음) |
    | `null` | 없음 | 없음 |

  - 이름표 문구는 초안이며 플레이 테스트에서 검토한다.
  - **심화 단계**: '+'도 이름표도 그리지 않고 DOM에도 두지 않는다. 띄어쓰기 틈만 보인다.
- **감수 기록**: 이번 원고에 한 교정을 차례대로 적는다. 예: ① 고침 /ㄷ/→/ㄴ/.
- **단추**
  - 교정 부호 넷: 고침표·뺌표·넣음표·합침표
  - [되돌리기]: 마지막 교정 하나를 취소
  - [송출]
  - [도움]
  - [다음 원고]
  - [게임 방법]
  - 소리 켜기/끄기

### 8-2. 교정 부호 (결정 0002)

- **고침표**
  - 음운 하나를 누르면 조음 도표가 열리고, 옮겨 갈 칸을 누르면 교체된다.
  - 자음은 음운 해전 체계표다(조음 위치 × 방법 × 세기, `SOUNDS`의 자질로 그림). 모음은 모음 도표(높이 × 앞뒤·입술)와 반모음 줄(j·w)이다.
  - 누른 음운 자리에 맞는 도표가 열린다: 초성·종성은 자음표, 중성은 모음표, 반모음 자리는 반모음 줄.
  - 지금과 같은 칸은 누를 수 없다(이미 그 음운).
- **닮은 칸 안내**: 1·2장 **기본 단계만** 켠다.
  - 학생이 누른 음운에 지금 상태에서 규칙이 걸리면, 그 규칙이 바꿀 칸을 도표에서 은은히 보인다(`G.rules.applicable`의 결과에서).
  - 규칙이 걸리지 않는 음운이면 아무 칸도 보이지 않는다. 그래서 감기의 /ㅁ/에는 아무것도 없고, 막론은 /ㄹ/을 먼저 눌러야 /ㄴ/ 칸이 보인다.
  - 심화 단계에서는 끈다.
- **뺌표**: 음운 하나를 누르면 그 음운을 뺀다.
- **넣음표**
  - 음절 사이 틈을 누르고 넣을 음운(/ㄴ/ 또는 반모음 j)을 고른다. /ㄴ/은 뒤 음절의 빈 초성에, j는 뒤 음절의 빈 반모음 자리에 들어간다.
  - 들어갈 빈자리가 없으면 그 자리에서 한 줄로 알리고 기록하지 않는다(원칙 3).
- **합침표**
  - 이웃한 두 음운을 차례로 누르면 조음 도표가 열리고, 합쳐진 결과 음운을 학생이 고른다. 게임이 결과를 계산해 보여 주지 않는다.
  - 이웃하지 않으면 한 줄로 알리고 기록하지 않는다.
- **연음은 교정하지 않는다**: 프롬프터에 옮길 때 저절로 이어 읽는다(`G.rules.reading`). 원고 상태는 표기의 음절 자리를 그대로 둔다.

### 8-3. 송출과 신호

1. [송출]을 누르면 `G.rules.broadcast(원고, 교정들)`로 판정한다.
2. **연출**
   - ON AIR 램프가 켜지고, 프롬프터에 아나운서가 읽는 발음(교정한 대로)이 한 음절씩 나타난다. 연출은 1.5초 안쪽이다(조정 가능).
   - 그다음 신호 한 줄이 나온다.
   - 움직임 줄이기가 켜져 있으면 연출 없이 곧바로 보인다.
3. **신호별 처리**

   | 신호 | 화면 | 다음 |
   |---|---|---|
   | 온에어 성공 | 감수 도장 | [다음 원고]가 앞에 온다 |
   | 결과는 맞지만 규칙 밖 | 규칙 밖 교정 표시 + [다시 감수]를 앞에 | [다시 감수]는 이 원고의 교정을 모두 지우고 다시 시작. [다음 원고]로도 갈 수 있음(결정 0012) |
   | n곳이 다름 | "n곳이 달라요". 다른 음절 **수만**, 위치는 도움 ① | 교정은 그대로 남아 계속 고칠 수 있음 |
   | 표준 아님 | 시청자 게시판 한 줄 "표준 발음이 아니에요" | 교정은 그대로 남음 |

4. **연음 안내 한 줄**: "연음은 소리가 바뀐 것이 아니에요"
   - **연음 자리의 받침**을 교정(고침·뺌)한 채로 송출하면 나온다. 연음 자리는 엔진이 정하는데, 뒤 음절이 빈 초성이고 그 사이 경계가 `formal`이나 `null`이라 읽을 때 저절로 옮겨지는 종성을 말한다(옷이의 /ㅅ/, 닭이의 /ㄹ/·/ㄱ/).
   - 이 판정은 `G.rules`의 순수 함수가 한다.
   - 한 줄 자리는 하나뿐이므로 차례로 보인다: 신호 줄이 먼저 나오고, 잠시 뒤(약 1.5초, 조정 가능) 같은 자리가 연음 안내로 바뀐다. 신호의 종류는 신호 기호(배지)로 계속 남는다. 신호가 '표준 아님'일 때도 같다(신호 먼저).
5. **송출 기록**: 원고마다 송출 횟수를 센다.

### 8-4. 도움 사다리 (한 칸씩 학생이 엶, 감점 없음)

- **① 다른 음절 위치**
  - 마지막 송출이 '다름'이면, 프롬프터 발음에서 다른 음절을 표시한다(`broadcast`의 `at`).
  - 아직 송출하지 않았거나 마지막 송출이 '다름'이 아니면 "먼저 송출해 보세요"만 보이고 도움으로 세지 않는다.
- **② 지침 다시 보기**: 이 장의 채운 감수 지침을 보인다.
- **③ 풀이 예시**: 이 원고가 아니라 **같은 규칙을 쓰는 다른 낱말**의 풀이를 보인다(표기 → 단계별 교정 → 발음).
  - 쌍둥이 원고 = 풀이 과정의 규칙 차례와 함정 종류가 같은 원고(대결에서도 쓸 함수).
  - 후보는 그 장 원고 풀에서 **이번에 뽑힌 7개를 빼고**, 표준 발음이 이 원고와 같은 것(낮·낯·낱처럼)도 뺀다. 뽑힌 원고의 답이 미리 새지 않게 하려는 것이다(원칙 5). 연음 함정이면 다른 연음 함정을 "교정 없이 송출"로 보인다.
  - 후보가 없으면(감기 등) ②처럼 지침을 보이고 "같은 풀이 예시가 없어요" 한 줄을 덧붙인다.
- 한 번이라도 연 원고는 '도움 받음'으로 기록한다(①이 "먼저 송출해 보세요"였던 경우는 빼고).

### 8-5. 다음 원고와 넘김

- [다음 원고]는 언제나 누를 수 있다(결정 이번 회차).
- 이 원고를 한 번도 송출하지 않았으면 "송출하지 않고 넘길까요?"를 한 번 묻는다. 게임 방법 창에는 "고칠 게 없으면 교정 없이 송출하세요"를 넣는다.
- **원고 결과**

  | 결과 | 언제 |
  |---|---|
  | 온에어 | 온에어 성공이 한 번이라도 있었음 |
  | 규칙 밖 | 성공은 없고, 마지막 송출이 '규칙 밖' |
  | 넘김 | 그 밖(송출 안 함, 마지막이 다름·표준 아님) |

- 7번째 원고 다음에는 조항 공개로 간다.

## 9. 조항 공개

- "선생님이 채운 지침은 실제로 「표준 발음법」 제N항입니다" 꼴로, 그 장 지침들의 조항과 이번에 뽑힌 원고 7개의 근거 조항을 합쳐 보인다(예: 2장은 제18·19·20항과 제21항, 놓는이 뽑혔으면 제12항). 차례는 조항 번호 순이고, '20-다만'은 제20항 바로 뒤다.
- 조항 원문은 **원문** 표시를 달아 보인다. 방송국·합침표 같은 게임 설정과 구분한다(결정 0001).
- 공개할 조항 목록은 `G.rules`의 순수 함수가 정한다.

## 10. 장 결과

- **원고별 줄(7개)**: 표기, 표준 발음(여기서 처음 보임), 결과(온에어·규칙 밖·넘김), 송출 횟수, 도움 받음.
- **이번 장 원고의 정답 기준 숫자**: 변동 유형별 횟수(교체·탈락·첨가·축약 — 7개 원고 `change`의 합)와 음운 수 변화(7개 원고 `count`의 표기→발음). 학생이 한 교정은 세지 않는다.
- **공개된 조항 목록**
- **단추**: [다시 하기](같은 장·같은 단계를 새로 뽑아 지침 없이 감수부터), [장 고르기].
- **저장**: 장 결과에 닿으면 진행 중인 장 저장을 지운다.

## 11. 이어 하기와 설정 저장

- **진행 중인 장은 기기에 하나**다. 새 장을 시작하면 바뀐다(§5의 확인).
- **저장할 것**
  - 학년, 장, 단계, 시드나 뽑힌 원고 id의 차례
  - 지금 단계(지침 / 감수 / 조항 공개)
  - 지침을 다 채웠는지
  - 끝난 원고의 결과·송출 횟수·도움 받음
  - 지금 원고의 교정 목록·송출 횟수·도움 받음(연 도움 단계)·마지막 송출 결과(신호 종류와 다른 음절 위치 `at` — 도움 ①이 씀)
- **저장 시점**: 교정·되돌리기·다시 감수·송출·도움·원고 넘김·지침 완료마다 저장한다. 새로 고침하면 하던 자리 그대로(지금 원고의 교정까지) 돌아온다.
- **버리는 경우**: 저장 형식 버전이 다르거나, 망가졌거나, 저장된 원고 id가 지금 원고 데이터에 없거나, 지침·원고 데이터가 바뀌어 맞지 않으면 그 진행 장을 조용히 버린다(오류 없이 시작 화면).
- **따로 저장하는 것**: 설정(소리·움직임 줄이기)과 마지막 선택(학년·단계), 게임 방법을 연 적 있는지는 진행 장과 따로 저장한다.
- **저장 이름**: 모두 한 접두사로 시작하고(예: `eumun-byeondong:` — 조정 가능), 값은 `{ s: 저장형식버전, … }` JSON이다.
- **예외를 던지지 않는다**: 저장소가 막혀도 이번 세션 동안은 메모리로 돈다. 저장 함수는 예외를 던지지 않고 `console.error`를 쓰지 않는다(음운 해전 `save.js`와 같은 방식).

## 12. 조항 원문 데이터

- **제15항 원고 보강**: 제15항 원문을 대조할 때 원문에 딸린 예시 낱말(예: 밭 아래, 늪 앞, 젖어미, 헛웃음, 꽃 위 — 원문에서 확인한 것만)도 확인한다. 지금 엔진(1·2장 규칙)으로 풀리는 것만 1장 원고로 더한다(형태소 경계·풀이 과정·음운 수·출처 '표준 15' 포함, 엔진 대조 통과). 그래야 지침 ③ 예시(3~4개)와 감수 원고 둘 다에 제15항 낱말이 있다. 대조할 수 없으면 더하지 않고 지침 ③ 예시는 겉옷·옷 위 2개로 한다. 그 경우 1장 감수에는 제15항 원고가 없음을 선생님께 알린다.
- 공개와 지침에 쓰는 표준 발음법 조항 원문을 데이터 파일 하나에 둔다. 대상은 제8·9항, 제12항 3, 제13·14·15·18·19항(붙임 포함), 제20항(다만 포함), 제21항이다.
- **원문 대조 후에만 넣는다.**
  - 지학사 지도서(`design/research/03` §4)에 실린 원문을 먼저 쓴다.
  - 없으면 03 §2가 쓴 규범 원문 미러 등 1차 원문을 확인해 03에 [원문 확인]으로 적는다.
  - 대조할 수 없는 조항은 넣지 않고 선생님께 알린다.
- **예시 낱말**: 조항 원문에 딸린 예시 낱말은 원문 그대로 둔다(장음 표시 포함).

## 13. 화면 문구

- 화면 문구는 화면 문구 파일(`js/data/text.js`, `TEXT` + `G.text`)에 둔다. 예외: 감수 지침 문장은 지침 데이터(`js/data/guides.js`)에, 조항 원문은 조항 데이터(`js/data/articles.js`)에 둔다. 세 파일 모두 같은 문구 규칙을 지키고 점검한다(금지 낱말·'글자'·한자 없음, 학년 키 구조, 빗금 표기 — 조항 원문은 원문 그대로이므로 빗금 표기만 예외). 화면 코드에 한국어 문장을 박지 않는다.
- 학년 키 `m3`·`h1`은 같은 키 구조다. 중3은 우리말 풀이, 고1은 우리말 + 한글 한자어 용어다(결정 0003).
- 신호·안내는 한 화면에 한 줄 자리 하나에, 줄바꿈 없이 대략 30자 이내로 쓴다. 게임 방법 창과 조항 원문만 여러 줄을 쓸 수 있다.
- 문구 초안은 에이전트가 쓰고 플레이 테스트에서 검토한다.

## 14. 화면 표현

- **분위기**: 밝은 방송국 감수실. 밝은 종이 바탕에 원고·교정 부호가 또렷하고, 프롬프터와 ON AIR 램프만 방송국 느낌을 낸다. 다크 모드는 없다.
- **색**: 색은 기본 토큰 파일의 토큰만 쓰고 역할을 섞지 않는다(신호 색 / 선택·강조 색 / 경계 종류 색). 신호는 색 + 기호로 구분한다.
- **그리는 방식**: 정확해야 하는 것은 코드로 그린 SVG다(음절 블록, 형태소 경계, 교정 부호, 조음 도표, 프롬프터, 신호 기호). 깜박임 반복이나 계속 움직이는 장식은 없다.
- **그림 자리**: 아나운서·감수실·시작 화면 그림이 들어갈 자리는 이번에 빈 틀로만 둔다(레이아웃만 잡음).
- **화면 크기**
  - 기준 크기: 태블릿·노트북 가로(1280×800, 1366×768), 휴대폰 세로(360×740, 390×844), 전자칠판(1920×1080). 모든 화면이 이 크기에서 가로 스크롤 없이 쓰여야 한다.
  - 누르는 자리: 가로 배치 64px 이상, 휴대폰 세로 48px 이상.
  - 휴대폰 세로에서 음절 블록이 한 줄에 들어가지 않으면(4음절 이상 등) 두 줄로 나눈다. 띄어쓰기·형태소 경계 자리에서 먼저 나누고, 줄이 바뀌는 곳의 틈(넣음표 자리)도 누를 수 있게 남긴다.
  - 휴대폰 가로처럼 낮은 화면에서는 '세로로 돌려 주세요'를 보인다(음운 해전과 같음).
- **글꼴**(Pretendard, SIL OFL — 음운 해전에서 이미 승인)
  - 발음 표시용 굵기 하나(Pretendard 700 — 음운 해전의 판 위 소리 표기와 같은 굵기, 음절 블록·프롬프터·발음 표기·제목)에는 현대 한글 음절 11,172자 전부와 호환 자모, 기본 라틴 글자, 장음 표시(ː) 등 필요한 기호를 담는다. 학생이 만든 어떤 음절도 깨지지 않게 하려는 것이다.
  - 안내 글 굵기는 화면에 쓰인 글자만 담는다.
  - OFL에 따라 글꼴 이름을 바꾸고 라이선스 파일을 함께 둔다.
  - 글꼴을 만드는 도구는 음운 해전 `tools/build_fonts.py`를 가져와(출처 표시) 고친다. 원본 글꼴은 선생님 PC의 음운 해전 `tools/fonts_src/`에 있는 것을 쓰고, 저장소에는 넣지 않는다.

## 15. 소리

- **소리 장치**: 음운 해전 `js/core/audio.js`를 가져와(출처 표시) 이 게임의 소리 자리에 맞춘다.
  - 기본 소리 자리(조정 가능)
    - 배경 음악: 감수(지침·감수 화면), 결과(조항 공개·장 결과)
    - 효과음: 교정, 송출, 온에어 성공, 규칙 밖, 다름, 표준 아님, 지침 맞음, 지침 틀림
  - 파일이 없어도 조용히 넘어간다(예외·`console.error` 없음). 첫 터치 뒤에 소리를 켠다.
- **후보 목록**: 자리마다 자유 이용 음원 후보 2~3개를 찾아 문서 하나에 모은다.
  - 적을 것: 링크, 만든 사람, 라이선스 CC0/CC BY 4.0, 길이, 고른 까닭.
  - 선생님이 링크로 들어 보고 고른다. 이번에는 **아무 음원도 내려받지 않는다**.

## 16. 화풍 견본

- **장면**: 밝은 방송국 감수실 장면 하나. 가상의 아나운서 1명이 프롬프터 앞에 있고 감수 책상이 함께 있다. 아나운서의 생김새는 견본을 보고 정한다.
- **화풍**: 2~3가지.
- **만드는 방법**: 음운 해전의 그림 도구(`tools/gen.ps1`, 출처 표시)로 만든다. 프롬프트는 영어(ASCII)로 `tools/prompts/`에 둔다.
- **금지**: 글자·숫자·로고·워터마크, 실제 방송사·인물, 조선 소재.
- **파일**: 원본은 저장소에 넣지 않는 폴더에 둔다. 선생님께 보일 축소본은 디자인 기록 폴더에 넣고 기록 문서에 프롬프트를 남긴다. 게임은 이번에 이 그림을 쓰지 않는다.

## 17. 엔진에 더할 순수 함수 (계약)

`G.rules`에 더한다. 모두 받은 값을 바꾸지 않고 JSON으로 옮길 수 있는 값을 돌려준다. 모양의 기준은 `rules.js` 머리 주석이다.

| 이름(제안) | 받는 것 → 돌려주는 것 |
|---|---|
| 원고 뽑기 | 장, 원고 풀, 뺄 id 목록, 난수 → 원고 id 7개(차례 포함). §6의 조건을 지킨다 |
| 원고 갈래 | 원고 → 갈래(§6의 정의: 끝소리가 아닌 첫 규칙 / 끝소리 / 함정 종류) |
| 쌍둥이 원고 | 원고, 원고 풀, 뺄 id 목록 → 규칙 차례·함정 종류가 같고 표준 발음이 다른 원고 하나 또는 없음(§8-4) |
| 지침 채점 | 지침들, 고른 값 → 틀린 칸 수 |
| 지침 예시 검증 | 지침 → 예시가 빈칸 조건을 모두 보이는지(점검용) |
| 공개할 조항 | 장의 지침들, 뽑힌 원고들 → 조항 목록(차례 고정) |
| 연음 자리 | 상태 → 연음 자리 종성 자리 목록 / 교정들 → 연음 자리 받침을 건드렸는지 |
| 닮은 칸 | 상태, 누른 자리 → 그 자리에 걸리는 규칙의 결과 음운 또는 없음 |
| 원고 결과 | 그 원고의 송출 기록 → 온에어 / 규칙 밖 / 넘김 |
| 장 정답 합계 | 원고들 → 변동 유형별 횟수 합, 음운 수 표기→발음 합 |

## 18. 꼭 해야 하는 점검

- **판정 기준**: `cd tests && npm test`가 '모두 통과'로 끝나야 한다. 실패한 채로 끝내지 않는다.
- **Node 점검(브라우저 없이)**
  - 지금 규칙 점검이 그대로 통과해야 한다.
  - §17의 함수마다 사례
    - 시드별 뽑기 결과가 결정적임
    - 1·2장의 모든 시드(예: 200개)에서 §6 조건이 지켜지고 예시 원고가 안 뽑힘
    - 감기·연음 함정의 쌍둥이 처리
    - 지침 채점
    - 지침 예시가 조건을 모두 보임
    - 공개 조항 집합
    - 연음 자리(옷이·닭이·불놀이의 놀|이)
    - 닮은 칸(감기 /ㅁ/ 없음, 막론 /ㄱ/ 먼저는 없음·/ㄹ/은 /ㄴ/)
  - 데이터·문구
    - `m3`·`h1` 키 구조 같음
    - 금지 낱말 없음(문구·지침·조항 파일 전체)
    - 한자 없음, 빗금 표기
    - 지침 예시 id가 원고에 있음
    - 조항 원문 파일에 필요한 조항이 다 있음
    - 새로 더한 제15항 원고가 엔진 대조를 통과함
  - 저장: 흉내 낸 저장소로 저장→복원이 같음, 망가진 값·다른 버전·없는 원고 id는 버림, 막힌 저장소에서 예외 없음.
- **브라우저 점검(aside만 — 결정 0008)**
  - 시작 화면이 콘솔 오류 없이 뜸(음원 파일 없음 상태 포함)
  - 1장·2장을 지침부터 결과까지 끝까지 해 봄(점검용 조작으로)
  - 신호 넷이 각각 나옴
  - 연음 안내가 조건대로 나옴
  - 넘김 확인 창
  - 되돌리기
  - 새로 고침 뒤 하던 자리 그대로(교정까지)
  - 심화 단계에서 경계가 DOM·aria에 없음
  - 표준 발음·정답이 결과 전에 화면 글·DOM에 없음
  - 다섯 크기에서 가로 스크롤 없음, 누르는 자리 크기, 한 줄 문구가 넘치지 않음
  - 화면 글 금지 낱말 없음
  - 발음용 글꼴이 아무 한글 음절이나 그림
- 점검용 값이나 조작은 점검 페이지·점검 대본에서만 쓰고, 게임 화면에 단추·글로 드러내지 않는다.

## 19. 판단의 까닭 (코드만 봐서는 알 수 없는 것)

- **원고를 무작위로 7개 뽑는 까닭**: 다시 해도 외워서 풀 수 없게 하려는 것이다. 2장 함정을 '다만 1 + 감기 1'로 고정한 것은, 무작위로 두면 감기(위치 동화 함정)가 열 판에 두 번 꼴로만 나오기 때문이다.
- **지침에 '다만'·겹받침 연음·제15항을 넣은 까닭**: 그것이 빠지면 함정을 규칙으로 풀 수 없고 찍기가 되기 때문이다. 예시를 고정한 까닭은, 무작위면 빈칸 근거가 안 나올 수 있기 때문이다.
- **풀이 예시를 다른 낱말로 보이는 까닭**: 도움 ①→②→③을 연달아 눌러 답을 베끼는 것을 막고, 규칙을 자기 낱말에 옮기게 하려는 것이다.
- **닮은 칸을 '규칙이 걸리는 자리에서만' 보이는 까닭**: '내 위치 × 이웃 소리의 방법'으로 정하면 감기 /ㅁ/→/ㅂ/, 막론 /ㄹ/→/ㄷ/처럼 틀린 길을 켠다. 대신 기본 단계에서는 답의 일부를 알려 주는 셈이고, 그래서 심화에서는 끈다.
- **연음 안내를 '연음 자리 받침 교정'으로 정한 까닭**: 넣음표 보기가 /ㄴ/·j뿐이라 '받침을 뒤로 옮기는 교정'은 거의 일어나지 않는다.
- **[다음 원고]를 늘 두되 송출 전에만 묻는 까닭**: 함정의 정답은 '교정 없이 송출'이다. 고칠 게 없다고 바르게 판단한 학생이 송출 없이 넘겨 '넘김'으로 남는 일을 줄이려는 것이다.
- **장 결과 숫자를 정답 기준으로 세는 까닭**: 디브리핑에서 모두가 같은 숫자를 보게 하려는 것이다.
- **글꼴을 발음용만 한글 전부로 담는 까닭**: 아나운서가 학생이 교정한 대로 읽으므로 어떤 음절이든 화면에 나올 수 있다. 음운 해전처럼 쓰인 글자만 담으면 발음 표시가 깨진다.
- **'글자' 금지와 한자를 쓰지 않는 까닭**: 음운·발음·표기를 섞지 않는 시리즈 원칙을 잇고, 고른 글꼴에 한자가 없기 때문이다.
- **이어 하기에서 덮어쓸 때 묻는 까닭**: 교실 기기를 여러 반이 돌려 쓰기 때문이다.
- **버린 안**
  - 경계 이름표 없이 모양만
  - 합침표 결과 자동 계산(답이 드러남)
  - 지침 3번 틀리면 정답 보기
  - 결과 숫자를 학생 교정 기준으로 세기
  - 모든 굵기 한글 전부(약 2MB)
  - 기기 기본 글꼴
  - 어두운 조정실 분위기
  - 그림·소리를 바로 넣기(고른 뒤 넣음)
